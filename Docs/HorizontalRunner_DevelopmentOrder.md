# 횡스크롤 러너(쿠키런 스타일) — 개발 순서 및 코드 작성 순서

현재 `PlayerController`는 좌우 이동 + 점프로 **월드 좌표에서 캐릭터가 이동**합니다. 목표는 **캐릭터 X는 고정(또는 미세 조정만), 배경·발판·아이템이 왼쪽으로 흘러가며** 난이도와 점수 체계를 쌓는 구조입니다. 아래 순서는 그 전환을 전제로 합니다.

---

## 1. 설계를 먼저 고정할 것 (코드 전)


| 항목       | 결정 포인트                                                            |
| -------- | ----------------------------------------------------------------- |
| **진행 축** | 카메라·캐릭터 기준 X 고정, 오브젝트는 `scrollSpeed`만큼 매 프레임 왼쪽(-X) 이동            |
| **물리**   | Rigidbody2D + Collider2D(발판·바닥·아이템) vs Transform 직접 이동 — 한 가지로 통일 |
| **좌표계**  | 발판/아이템을 **월드 좌표**로 스폰할지, **캐릭터 기준 상대**로 둘지                        |
| **난이도**  | `scrollSpeed`를 시간에 따라 올릴지, 별도 웨이브인지                               |


이 문서의 코드 순서는 **Rigidbody2D 없이 Transform 스크롤**으로도, **2D 물리**로도 적용 가능하도록 단계를 나눕니다.

---

## 2. 개발 순서(기능 단위)

### 단계 A — “세상이 움직인다” (스크롤 코어)

1. **전역 진행 속도**
  - 예: `GameScroll` 또는 `RunSession` 싱글톤/정적 필드에 `float ScrollSpeed`.  
  - 나중에 가속·일시정지·게임 오버 시 한곳에서 끄기 쉽게 유지.
2. **스크롤 대상 분리**
  - 배경 레이어, 발판 부모, 아이템 부모 등 **움직여야 할 오브젝트만** `IScrollable` 또는 공통 부모 `ScrollRoot` 아래에 두기.
3. **스크롤 컴포넌트**
  - `Update`에서 `transform.position += Vector3.left * scrollSpeed * Time.deltaTime` (또는 Rigidbody면 `velocity`).

**검증:** 플레이어 입력 없이도 배경만 흘러가 보이면 OK.

---

### 단계 B — 플레이어를 “러너”로 바꾸기

1. **수평 이동 제거 또는 축소**
  - 좌우 키로 `transform.Translate` 하던 부분 제거.  
  - 달리기 애니메이션은 **항상 달리기** 또는 `ScrollSpeed > 0`일 때만 재생하도록 조건 변경.
2. **점프만 유지**
  - 점프는 Y만 변경 (현재 구조와 호환).  
  - 착지 판정은 아래 단계 C에서 발판과 함께 `Grounded`/`OnPlatform`로 정리하는 편이 안전.
3. **(선택) 레인**
  - 2~3줄 레인이면 Z 또는 X를 소량만 바꿔 레인 전환.

**검증:** 캐릭터 X가 고정된 상태에서 점프만 가능.

---

### 단계 C — 발판(밟을 수 있는 지형)

1. **프리팹**
  - `BoxCollider2D`(또는 TilemapCollider2D)가 있는 발판 프리팹 1종 이상.
2. **스폰**
  - 화면 오른쪽 밖에서 스폰 → 스크롤로 왼쪽으로 이동.  
  - **스폰 간격·높이**를 `ScriptableObject` 또는 인스펙터 필드로 조절 가능하게.
3. **재사용(오브젝트 풀)**
  - 화면 왼쪽 밖으로 나가면 비활성화 후 풀에 반환. (인스턴스 난립 방지)
4. **착지**
  - 물리 사용 시: `Rigidbody2D` + `Collider2D` + 바닥 레이어.  
  - 물리 미사용 시: 발판 상단 Y와 플레이어 하단을 맞추는 방식은 유지보수가 어려우므로 **2D 물리 권장**.

**검증:** 연속 점프로 여러 발판을 밟고 넘어갈 수 있음.

---

### 단계 D — 아이템과 점수

1. **아이템 프리팹**
  - `Collider2D` + `isTrigger = true`, `ItemPickup` 스크립트.
2. **수집**
  - `OnTriggerEnter2D`에서 `ScoreManager.AddScore(value)` 호출 후 비활성/풀 반환.
3. **점수**
  - `ScoreManager`(싱글톤 또는 이벤트)에서 점수 보관 + UI 갱신 이벤트.
4. **스폰 타이밍**
  - 발판 스폰과 같은 루틴에서 확률/고정 슬롯으로 배치하거나, 별도 `ItemSpawner`.

**검증:** 아이템 획득 시 점수만 오르고 중복 획득이 없음.

---

### 단계 E — UI·게임 상태

1. 점수 텍스트, (선택) 체력/거리.
2. `GameState`: Playing / Paused / GameOver — 스크롤·스폰·입력 on/off.

---

### 단계 F — 폴리시

- 충돌 레이어 마스크 정리.  
- `scrollSpeed` 가속 곡선.  
- 사운드, 이펙트, 간단한 튜토리얼 씬.

---

## 3. 코드 작성 순서(파일·클래스 관점)

아래는 **의존성이 앞쪽을 덜 타도록** 정한 순서입니다.


| 순서  | 만들 것                               | 역할                                                  |
| --- | ---------------------------------- | --------------------------------------------------- |
| 1   | `GameSession` 또는 `RunSettings`     | `ScrollSpeed`, 가속, 게임 오버 플래그 등 세션 단위 값              |
| 2   | `ScrollMover` (또는 `ParallaxLayer`) | `ScrollSpeed`를 읽어 자신(또는 자식)을 -X로 이동. 배경은 속도 배수만 다르게 |
| 3   | `PlayerController` 수정              | 좌우 이동 제거, 점프·애니 조건 정리, (필요 시) `Rigidbody2D` 연동      |
| 4   | `PlatformPool` + `PlatformSpawner` | 풀, 스폰 위치, 간격, 풀 반환 기준(화면 밖)                         |
| 5   | `ItemPickup` + `ItemPool` / 스포너 연동 | 트리거 수집, 점수 위임                                       |
| 6   | `ScoreManager`                     | 점수, UI 이벤트                                          |
| 7   | `UIGameHUD`                        | 점수 표시만 먼저                                           |
| 8   | `GameStateController`              | 시작/재시작/일시정지 시 스크롤·스포너 정지                            |


**참고:** `PlayerController`의 애니메이터를 매 프레임 `runtimeAnimatorController`로 바꾸는 방식은 부담이 큽니다. 스크롤 구조 안정화 후 **Animator 파라미터(`Speed`, `IsGrounded`, `Jump`) 한 개 컨트롤러**로 합치는 리팩터를 중기에 권장합니다.

---

## 4. 씬 구성 권장(인스펙터 작업 순서)

1. 빈 `ScrollRoot` — 발판·아이템 부모를 그 아래에 둠.
2. 배경을 레이어별 자식으로 두고 `ScrollMover`에 속도 배수만 다르게.
3. 플레이어는 `ScrollRoot` 밖(월드 고정) 또는 카메라 자식.
4. 스포너 오브젝트 1개에 `PlatformSpawner` 부착, 풀 프리팹 연결.
5. UI Canvas + `ScoreManager` 연결.

---

## 5. 현재 코드와의 연결 메모

- `PlayerController`의 `moveDirection`·`Translate`(좌우)는 **단계 B**에서 제거하거나 레인 전환용으로만 축소합니다.  
- 점프의 `startPosition.y` 보존 로직은 발판 위에서도 동작하도록 하려면 **착지 시 `startPosition`/`transform.position` 동기화**가 필요할 수 있습니다(단계 C 이후 조정).

---

이 문서 순서대로 진행하면 “배경 스크롤 → 플레이어 역할 변경 → 발판 → 아이템·점수 → UI·상태”로 커밋 단위도 나누기 쉽습니다.
